# Attack case catalogue — p01, p02, p03, p04 (UE-associated mobility/release surface)

All four are **UE-associated NGAP** initiating messages from an NG-RAN node to the AMF.
The shared weakness is that the AMF locates the victim UE context by **`AMF-UE-NGAP-ID`
alone** (Source AMF-UE-NGAP-ID for Path Switch) without binding the message to the UE's
current serving gNB / SCTP association / stored `RAN-UE-NGAP-ID`. A rogue but
NG-Setup-accepted gNB can therefore act on a UE served by another legitimate gNB
(**AMF-as-confused-deputy**): switch/redirect its N3 downlink, release it, force its
relocation, or cancel its in-progress handover.

| p02 | UEContextReleaseRequest | 42 | ignore | AMF-UE-NGAP-ID (10, reject), RAN-UE-NGAP-ID (85, reject), Cause (15, ignore), **PDUSessionResourceListCxtRelReq (133, reject, optional)** |
| p03 | HandoverRequired | 12 | reject | AMF-UE-NGAP-ID (10), RAN-UE-NGAP-ID (85), HandoverType (29), Cause (15), TargetID (105), PDUSessionResourceListHORqd (61), SourceToTarget-TransparentContainer (101) |
| p04 | HandoverCancel | 10 | reject | AMF-UE-NGAP-ID (10, reject), RAN-UE-NGAP-ID (85, reject), Cause (15, ignore) |

NEW builder added in `ngaptester/cases_p01_p04.py`: **`handover_cancel(amf_ue_id, ran_ue_id, cause)`**
(procCode 10; IEs 10/85/15). Two local wrappers post-process an existing builder to add an
optional IE the current builder cannot express: `path_switch_failed_list` (adds IE 57) and
`ue_ctx_release_with_pdu_list` (adds IE 133).

## Notes on realization

- **p01 params:** `attacker_ip`/`teid` drive the DL-NGU tunnel (redirect vs blackhole vs churn); `ran_ue_id` positional arg is the attacker-local RAN-UE-NGAP-ID (misbinding); `nci` overrides the claimed NR-CGI (location poison). The optional Failed-to-Setup list (IE 57) is not a `path_switch_request` param, so p01-d uses the local wrapper `path_switch_failed_list`.
- **p02 optional list:** IE `PDUSessionResourceListCxtRelReq` (133) is not a `ue_context_release_request` param → local wrapper `ue_ctx_release_with_pdu_list`. p02-a/c/d/e/g differ only by `amf_ue_id` / `ran_ue_id` / `cause`, which are exactly the distinguishing IEs for those rows.
- **p03:** all six rows realizable through existing `handover_required` params (`target_gnb_id`, `cause`, `pdu_sessions`, `src2tgt_container`, and the `amf_ue_id`/`ran_ue_id` positionals).
- **p04:** HandoverCancel has only three IEs (10/85/15); every row is realized by the NEW `handover_cancel` builder varying `amf_ue_id` / `ran_ue_id` / `cause`. Timing/procedure-state distinctions (d/e/f) are not expressible in the encoded PDU and are captured via Cause and the target UE id.
- **Validation:** `python -c "from ngaptester.cases_p01_p04 import CASES,CFG; from ngaptester import ngap; [ngap.encode(c['build'](CFG)) for c in CASES]; print('ALL ENCODE OK', len(CASES))"` → `ALL ENCODE OK 25`.
